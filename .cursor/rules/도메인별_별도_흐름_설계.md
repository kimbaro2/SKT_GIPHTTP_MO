# 도메인별 별도 흐름 설계

## 원칙
- **MO는 subcode를 구분하지 않는다.** (SM_REQ_SIMPLE / SM_REQ_TRANS_RESULT 등 subcode별 분기 없이 MO 처리. 관련 로직 수정은 별도 반영.)
- **공통 흐름이 아니라** 각 도메인(NORMAL_MO, NOTI_PLUS, NOTI_REGISTERED, CHARACTER_1584, FORWARD 등)마다 **별도 흐름**으로 구성한다.
- **도메인별 INSERT**는 **별도 기능**으로 분리(IMoDomainInsert 구현체). 모든 도메인 공통 적용.
- **B안** 채택: 핸들러 `handle()` 내부에서 흐름 수행. 흐름은 `processSMReqSimpleWithInsert` + 도메인 INSERT(registry) 호출로 구현.

## 목표 구조 (B안 + 도메인별 INSERT 별도 기능)

| 도메인 | 담당 핸들러 | INSERT 구현체 | 비고 |
|--------|-------------|---------------|------|
| NORMAL_MO | NormalMoHandler | NormalMoInsert | Relay → insertRelayMOCallInfo, 그 외 → insertGIPMOCallInfo |
| NOTI_PLUS | NotiPlusHandler | NotiPlusInsert | insertMO_NOTISEND |
| NOTI_REGISTERED | NotiRegisteredHandler | NotiRegisteredInsert | insertMO_NOTISEND |
| CHARACTER_1584 | Character1584Handler | Character1584Insert | 1584 entity 재조회 후 insertGIPMOCallInfo |
| FORWARD | ForwardHandler | ForwardInsert | Relay 또는 insertGIPMOCallInfo |
| CDMA_ROAMING, GSM_ROAMING, SMS_MANAGER_638, SMS_MESSENGER_2580, SPECIAL_SHARP | 각 핸들러 | GipMoInsert | insertGIPMOCallInfo 공통 |

## 흐름 단계 (handle() → processSMReqSimpleWithInsert 내부)
1. **QITEM 변수체크** — `handler.checkQItemVariables(qItem, context)`
2. **한도 체크** — MO 한도 / GIVE 한도
3. **CP 전송** — `moSendToCpService.sendMoMessageToCp(...)`
4. **전송 실패 시** — requeue 후 return
5. **ucServerType 설정** — `VSMSS_TYPE`
6. **MO 전송 성공 통계** — `handler.recordMoSuccessInsqStat(qItem, context)`
7. **도메인별 INSERT** — `moDomainInsertRegistry.getInsert(serviceType()).insert(insertContext)` (별도 기능)
8. **MO-ACK** — `smsResService.processSMRes(...)` (dbInsertOk && moSendSuccess 시)
9. **과금 통계** — `handler.recordMoAckBilling(qItem, context, billType)` (freeBill 아닐 때)

## 구현 방식 (B안 — handle()에서 각각 구현)
- **B. 핸들러 내부에 흐름 전부 구현**  
  각 핸들러의 `handle()` 안에 QITEM 검증·한도·전송·**InsqStat**·**DB Insert**·MO-ACK·과금 등 **전체 단계를 각각 구현**.  
  **processSMReqSimpleWithInsert + registry 위임 사용 금지** — 위처럼 `runBlocking { moProcessorOps.processSMReqSimpleWithInsert(...) { registry.getInsert(...).insert(it) } }` 패턴으로 진행하지 않음.  
  InsqStat, DB Insert 등 공통 분모라고 해도 **각 도메인에서 각각 호출/구현**하도록 함.

## 인터페이스
- **IMoDomainInsert**: `serviceTypes(): Set<MoServiceType>`, `suspend fun insert(context: MoInsertContext): Int`  
  도메인별 INSERT만 담당. NormalMoInsert, NotiPlusInsert, NotiRegisteredInsert, Character1584Insert, ForwardInsert, GipMoInsert 등.
- **MoDomainInsertRegistry**: `getInsert(serviceType): IMoDomainInsert` — MoServiceType별 INSERT 구현체 조회.

## 구현 상태 (목표)
- **각 도메인 handle()**: QITEM 검증·한도·전송·InsqStat·DB Insert·MO-ACK·과금을 **handle()(또는 handle에서 호출하는 private 메서드) 안에서 각각 구현**. processSMReqSimpleWithInsert/registry 위임 사용하지 않음.
- InsqStat, DB Insert: 공통 분모라도 **각 핸들러에서 직접 호출**하도록 구현.
